= Configfile Reference — HoL Provisioner
:toc: preamble
:icons: font

Both AWS and Azure provisioners read a flat `configfile` mounted at `/userconfig/configfile`. Copy the example from your build directory:

* AWS: link:../../OnCloud/AWS/build/configuration/configfile.example[`OnCloud/AWS/build/configuration/configfile.example`]
* Azure: link:../../OnCloud/Azure/build/configuration/configfile.example[`OnCloud/Azure/build/configuration/configfile.example`]

== Format rules

* File name must be exactly `configfile` (no extension).
* One key per line: `KEY:value` — no quotes, no blank line after the last entry.
* Lines starting with `#` are comments (ignored when copying; remove for production).

== Data service sizing (optional)

The provisioner applies cloud-specific defaults for data service compute sizing on AWS and Azure; leave the keys below commented unless you need a non-default size. CDE and CAI use built-in defaults when `CDE_INSTANCE_TYPE` / `CAI_WS_INSTANCE_TYPE` are omitted (`m5.2xlarge` on AWS; `Standard_D8s_v5` on Azure). On Azure, `resolve_azure_instance_type` in `hol-functions.sh` verifies the requested SKU in `AZURE_REGION` and falls back through the supported list. Azure CDW activation uses the Azure-specific CDP operation with the environment CRN, subnet, and managed identity, allowing CDP to select the supported cluster compute configuration. CDF enable omits `instance_type` unless `CDF_INSTANCE_TYPE` is set, so CDP chooses the default Kubernetes node type.

|===
| Key | Services | Description

| `CDW_VRTL_WAREHOUSE_SIZE`
| CDW
| Virtual warehouse size

| `CDW_DATAVIZ_SIZE`
| CDW
| Data visualization instance size

| `CDW_TRINO_INSTANCE_TYPE`
| CDW
| Trino Virtual Warehouse instance type. Default `AUTO` resolves and validates the current CDP cloud default at deployment time. See <<cdw-virtual-warehouse-instance-types>>.

| `CDW_AUTOSUSPEND`
| CDW
| `true` (default) enables auto-suspend for Hive, Impala, and Trino Virtual Warehouses; `false` keeps them running.

| `CDW_AUTOSUSPEND_TIMEOUT_SECONDS`
| CDW
| Idle time before auto-suspend, in seconds (default `300`).

| `CDE_INSTANCE_TYPE`
| CDE
| CDE service cluster instance type. AWS default `m5.2xlarge`. Azure default `Standard_D8s_v5`; provisioner fallbacks include `Standard_D8as_v5`, `Standard_D8ds_v5`, `Standard_D16s_v5` (pick from the CDE UI workload dropdown for your region)

| `CDE_INITIAL_INSTANCES` / `CDE_MIN_INSTANCES` / `CDE_MAX_INSTANCES`
| CDE
| CDE cluster scaling bounds

| `CDE_SPARK_VERSION`
| CDE
| Spark version for `cdp de create-vc` (`AUTO`, `SPARK3_5_4`, `SPARK3_5`, etc.). `AUTO` maps to `SPARK3_5_4` on Datalake 7.3+; avoid `SPARK3` on 7.3.x (resolves to Spark 3.2.x and fails runtime catalog lookup).

| `CDE_VC_TIER`
| CDE
| Virtual cluster tier: `CORE` (default; HoL 1-1 on Core pool) or `ALLP` (All Purpose pool). Jenkins DeployHoL and PollSCM default `CORE` when unset.

| `CAI_WS_INSTANCE_TYPE`
| CAI
| CAI workspace instance type. AWS default `m5.2xlarge`. Azure default `Standard_D8s_v5` (same v5 family fallbacks as CDE)

| `CAI_MIN_INSTANCES` / `CAI_MAX_INSTANCES`
| CAI
| CAI workspace scaling bounds

| `CAI_ENABLE_GPU`
| CAI
| `yes` or `no`

| `CAI_GPU_INSTANCE_TYPE` / `CAI_MIN_GPU_INSTANCES` / `CAI_MAX_GPU_INSTANCES`
| CAI (AWS)
| GPU workspace settings

| `CAI_NFS_VERSION`
| CAI (Azure)
| NFS version for existing NFS mount (default `4.1`)

| `CDF_INSTANCE_TYPE`
| CDF
| Optional. When unset, CDF enable omits instance type and CDP chooses the default Kubernetes node type. Set only when the CDP actor may use custom DataFlow instance types (for example `m5.2xlarge` on AWS or `Standard_D8s_v5` on Azure). Requires environment-scoped `DFAdmin` on the API caller (`assignCdpEnvAdminRoles.sh` runs after Terraform on provision).

| `CDF_MIN_NODES` / `CDF_MAX_NODES`
| CDF
| CDF node count bounds (`--min-k8s-node-count` / `--max-k8s-node-count`)

| `CDF_USE_PUBLIC_LB`
| CDF
| `yes` or `no` — public load balancer for the CDF service. Cluster and load-balancer subnets come from CDP Terraform outputs, not configfile.
|===

[[cdw-virtual-warehouse-instance-types]]
=== CDW Virtual Warehouse instance types

CDP maintains separate instance-type catalogs for Hive, Impala, and Trino on each cloud. The provisioner queries `cdp dw describe-allowed-instance-types` before creating the warehouses. Hive and Impala use the current CDP defaults. `CDW_TRINO_INSTANCE_TYPE:AUTO` uses the current Trino default; an explicit Trino override must appear in the corresponding `trino.allowed` list or provisioning fails before warehouse creation.

Supported types reported by CDP on 2026-09-25:

|===
| Cloud | Engine | Default | Supported instance types

| AWS
| Hive
| `r5d.4xlarge`
| `r5d.4xlarge`, `r5ad.4xlarge`, `r5dn.4xlarge`, `r6id.4xlarge`, `r6gd.4xlarge`, `r7gd.4xlarge`

| AWS
| Impala
| `r5d.4xlarge`
| `r5d.4xlarge`, `r5ad.4xlarge`, `r5dn.4xlarge`, `r6id.4xlarge`, `r6gd.4xlarge`, `r7gd.4xlarge`

| AWS
| Trino
| `r5d.4xlarge`
| `r5d.4xlarge`, `r5ad.4xlarge`, `r5dn.4xlarge`, `r6id.4xlarge`

| Azure
| Hive
| `Standard_E16ds_v5`
| `Standard_E16ads_v5`, `Standard_E16ds_v5`, `Standard_E16pds_v5`

| Azure
| Impala
| `Standard_E16ds_v5`
| `Standard_E16ads_v5`, `Standard_E16ds_v5`, `Standard_E16pds_v5`

| Azure
| Trino
| `Standard_E16ds_v5`
| `Standard_E16ads_v5`, `Standard_E16ds_v5`
|===

The CDP service controls this catalog and may change it independently of the provisioner. View the current values with:

[source,bash]
----
cdp dw describe-allowed-instance-types \
  | jq '{
      aws: {hive: .aws.hive, impala: .aws.impala, trino: .aws.trino},
      azure: {hive: .azure.hive, impala: .azure.impala, trino: .azure.trino}
    }'
----

== Output

After a successful provision, workshop access details are written to:

[source]
----
/userconfig/{WORKSHOP_NAME}.txt
----

Jenkins attaches this file to the success email when run from CI.
