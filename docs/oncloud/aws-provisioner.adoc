== Overview

Hands-on Labs showcase Cloudera Data Platform Public Cloud to partners and customers. **AutoClouderaDeploy** is a container-based solution that provisions disposable on-demand infrastructure with a single command:

1. Cloudera Environment
2. Datalake
3. Data Services (CAI, CDW, CDE, and CDF)
4. Keycloak server (optional)
5. Workshop users

== Technology stack

1. Ansible
2. Terraform
3. Cloudera.cloud
4. CDP-tf-quickstarts
5. CDPY
6. CDP CLI
7. AWS CLI
8. Shell scripting

All tools are packaged in a Docker container.

== Jenkins and configfile parameters

* *OWNER* (resource tag `pse-owner`): default `pse-apac@cloudera.com`. Cannot use `owner` — CDP reserves it as a default tag.
* *LOCAL_MACHINE_IP*: IP or CIDR to whitelist for environment access. Default `0.0.0.0/0` is allowed for most deployments.
* *PROVISION_CAII*: when set to `YES`, `LOCAL_MACHINE_IP` **must not** be `0.0.0.0/0`. Use your Jenkins agent IP or a Cloudera VPN address: `208.127.31.110/32` or `208.127.31.11/32`.

The same CAII restriction is enforced in Jenkins parameter validation and in the container `configfile` check at runtime.

After a successful provision, access details are written to `/userconfig/{WORKSHOP_NAME}.txt` inside the container (your mounted userconfig on the host) and attached to the Jenkins success email when run from CI.

See link:configfile-reference.adoc[configfile reference] for all supported keys.

== Major features

1. Ubuntu Linux-based base image
2. Optional Keycloak VM with SSO access for workshop users (HTTPS via Let's Encrypt)
3. Workshop users mapped to CDP IAM groups with least-privilege roles
4. Parameterized Keycloak admin password
5. AWS and CDP prerequisite checks (VPC, Elastic IP, S3, IAM users/groups, SAML IdP quotas)
6. Optional activation of CDW, CDE, CAI, and CDF data services (parallel when multiple are selected; enable/disable playbooks skip redundant API calls when a service is already healthy or absent)
7. Idempotent provision and destroy workflows (CDF disable resolves service CRN, stops flows, terminates deployments, then `cdp df disable-service --terminate-deployments --no-persist`)
8. Uses `cdp-tf-quickstarts` Terraform modules pulled at runtime
9. Dynamic CDW virtual warehouse count based on workshop user count
10. Optional GPU-backed CAI workspaces
11. Configurable data service sizing and Spark version overrides
12. CDV and Data Catalog deployment with CDW
13. Multiple AWS authentication options (see below)
14. Parallel data service provisioning when multiple services are selected
15. Post-provision enhancements (link:aws-enhancements.adoc[S3 lifecycle and dladmin log policy])

== AWS authentication

The provisioner supports three authentication mechanisms:

a) *Access key* — `AWS_ACCESS_KEY_ID` and `AWS_SECRET_ACCESS_KEY` (via `~/.aws` mount or configfile)

b) *AWS SSO* — via Okta/SAML profile in `~/.aws`

c) *Instance role* — role assignment to the deployer EC2 instance via `sts:AssumeRole`

== Destroy pipeline and troubleshooting

The container `destroy` action runs, in order:

1. CAII teardown (when `PROVISION_CAII=YES`)
2. Disable data services (Ansible; CDW, CDE, CAI, CDF as configured)
3. Keycloak IDP user teardown (when Keycloak is enabled)
4. `destroy_hol_infra`: Keycloak Terraform (optional) → detach HoL `dladmin_log_policy` → CDP quickstart Terraform

The CDP environment and VPC are removed by **CDP quickstart Terraform destroy**, not by a separate `cdp environments delete` CLI call. Before Terraform runs, the automation:

* Disable playbooks poll until data services leave CDP list APIs; **`destroy_cdp` does not re-check list APIs** after a successful disable step (avoids stale CDP rows blocking Terraform). Teardown failures still fail the pipeline at `disable_data_services`. Optional extra poll: `HOL_CDP_DS_DESTROY_WAIT_SEC` (default **0**, used only if `hol_cdp_assert_data_services_absent_before_destroy` is invoked elsewhere)
* When `HOL_CDP_DELETE_ENV_BEFORE_TF=1` (default), calls **`cdp environments delete-environment`** for `{workshop}-cdp-env` and waits — this tears down CDP-managed CloudFormation, EKS, and ELB dependencies that block VPC/subnet/IGW deletion (fixing the case where NAT/ENI leaf scans are empty but Terraform still hangs)
* If the environment is already in a deleting state, waits until it is gone or idle (`HOL_CDP_ENV_DESTROY_WAIT_SEC`, default 3600)
* Optionally prepares the **workshop VPC only** (from Terraform state/output or EC2 Name tag `{workshop}-net`): delete NAT gateways, disassociate Elastic IPs on non-NAT ENIs in that VPC, release unassociated workshop-tagged EIPs, delete `available` ENIs, poll until no ENIs have mapped public IPs (`HOL_AWS_VPC_DESTROY_PREP=1`, default on)
* If mapped public IPs remain after prep, **fail fast** with a *Leaf blockers for Internet Gateway detach* trace (NAT gateways, ENIs with public IPs) instead of running Terraform for long periods with no AWS progress
* Caps each Terraform destroy attempt at `HOL_CDP_TERRAFORM_DESTROY_ATTEMPT_SEC` (default 900s); on timeout or *Still destroying…* on IGW/subnets, prints the leaf trace and retries after prep
* Retries CDP Terraform destroy when AWS returns `DependencyViolation`, `DetachInternetGateway`, or *mapped public address* errors (`HOL_CDP_TERRAFORM_DESTROY_MAX_ATTEMPTS`, default 12)

If Terraform logs *Still destroying...* on `aws_internet_gateway` or subnets for many minutes while the AWS console shows no IGW delete in progress, AWS is usually blocking Internet Gateway detach because ENIs or Elastic IPs in the workshop VPC still have public addresses (often left behind after CDP data service teardown).

=== Manual cleanup (workshop VPC only)

Replace `{workshop}` and set the AWS region (for example `us-west-1`). Resolve the VPC id from the `{workshop}-net` Name tag or your Terraform state.

[source,bash]
----
export AWS_REGION=us-west-1
WORKSHOP=cicd148
VPC=$(aws ec2 describe-vpcs --filters "Name=tag:Name,Values=${WORKSHOP}-net" \
  --query 'Vpcs[0].VpcId' --output text)

aws ec2 describe-network-interfaces --filters Name=vpc-id,Values=$VPC \
  --query 'NetworkInterfaces[].[NetworkInterfaceId,Status,Description,Association.PublicIp,Attachment.InstanceId]' \
  --output table

aws ec2 describe-addresses --filters Name=domain,Values=vpc \
  --query 'Addresses[?NetworkInterfaceId!=`null`].[AllocationId,PublicIp,NetworkInterfaceId,AssociationId]' \
  --output table

aws ec2 describe-nat-gateways --filter Name=vpc-id,Values=$VPC \
  --query 'NatGateways[?State!=`deleted`].[NatGatewayId,State]' --output table
----

Disassociate Elastic IPs on **non-NAT** ENIs in this VPC (`aws ec2 disassociate-address --association-id …`). **Do not** disassociate Elastic IPs on ENIs whose description is *Interface for NAT Gateway* — delete the NAT gateway (`aws ec2 delete-nat-gateway --nat-gateway-id …`) and wait until it is `deleted`. Then retry HoL **destroy**. Do not release or delete resources outside the workshop VPC.

Opt out of automated VPC cleanup with `HOL_AWS_VPC_DESTROY_PREP=0` on the destroy container. Opt out of `delete-environment` with `HOL_CDP_DELETE_ENV_BEFORE_TF=0` (not recommended — Terraform-only destroy often leaves CDP stacks in the VPC).

==== Dependency graph (when leaf NAT/ENI scans are empty)

Mapped public addresses and subnet dependencies often come from **parent** resources, not a lone Elastic IP:

[source,bash]
----
export AWS_REGION=us-west-1
WORKSHOP=cicd148
VPC=vpc-096c8991b47a2fbdb

cdp environments describe-environment --environment-name ${WORKSHOP}-cdp-env 2>/dev/null | jq -r '.environment.status // "absent"'

aws elbv2 describe-load-balancers --region "$AWS_REGION" --output json \
  | jq -r --arg vpc "$VPC" '.LoadBalancers[]? | select(.VpcId==$vpc) | [.LoadBalancerName,.Type,.Scheme,.State.Code] | @tsv'

aws cloudformation list-stacks --region "$AWS_REGION" --output json \
  | jq -r --arg p "$WORKSHOP" '.StackSummaries[]? | select(.StackStatus!="DELETE_COMPLETE") | select(.StackName|test($p;"i")) | [.StackName,.StackStatus] | @tsv'

aws ec2 describe-network-interfaces --region "$AWS_REGION" --filters Name=vpc-id,Values=$VPC \
  --query 'NetworkInterfaces[].[NetworkInterfaceId,Status,InterfaceType,Description,Association.PublicIp]' --output table
----

Delete the **CDP environment** and any remaining **data services** in the CDP UI first; then delete CloudFormation stacks or load balancers that reference the workshop name; only then retry quickstart Terraform destroy.

==== Example: cicd148 VPC blocked on IGW detach

Console error: *Network has some mapped public address(es). Please unmap before detaching gateway* on IGW `igw-0a16ec2302a93401a` / VPC `vpc-096c8991b47a2fbdb` (`cicd148-net`). After CDP data services and the environment are gone, list dependencies:

[source,bash]
----
export AWS_REGION=us-west-1
export VPC_ID=vpc-096c8991b47a2fbdb

aws ec2 describe-network-interfaces \
  --region "$AWS_REGION" \
  --filters "Name=vpc-id,Values=${VPC_ID}" \
  --query 'NetworkInterfaces[].{Eni:NetworkInterfaceId,Status:Status,PublicIp:Association.PublicIp,AssociationId:Association.AssociationId,Description:Description,Subnet:SubnetId}' \
  --output table

aws ec2 describe-network-interfaces \
  --region "$AWS_REGION" \
  --filters "Name=vpc-id,Values=${VPC_ID}" \
  --output json \
  | jq -r '.NetworkInterfaces[] | select(.Association.PublicIp != null) | [.NetworkInterfaceId,.Status,.Association.PublicIp,.Association.AssociationId,.Description] | @tsv'

aws ec2 describe-addresses --region "$AWS_REGION" --output json \
  | jq -r '.Addresses[] | [.PublicIp, .AllocationId, (.AssociationId // "none"), (.NetworkInterfaceId // "none")] | @tsv'

aws ec2 describe-nat-gateways --region "$AWS_REGION" \
  --filter "Name=vpc-id,Values=${VPC_ID}" \
  --query 'NatGateways[].{NatGatewayId:NatGatewayId,State:State,SubnetId:SubnetId,PublicIp:NatGatewayAddresses[0].PublicIp}' \
  --output table
----

Then disassociate (`aws ec2 disassociate-address --association-id …`), delete **available** ENIs, delete NAT gateways and release their allocation IDs, and retry destroy only when the ENI list shows no `PublicIp`.
