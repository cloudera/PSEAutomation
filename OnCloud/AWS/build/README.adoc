= AutoClouderaDeploy — AWS HoL Provisioner
:toc: preamble
:icons: font

Container-based automation that provisions a **disposable** Cloudera Data Platform Public Cloud Hands-on Lab stack on AWS — environment, datalake, data services (CAI, CDW, CDE, CDF), optional Keycloak SSO, and workshop users.

Detailed reference: link:../../../docs/oncloud/aws-provisioner.adoc[AWS provisioner guide] · link:../../../docs/oncloud/configfile-reference.adoc[configfile reference]

== Quick start

=== 1. Prerequisites

[source,bash]
----
aws login          # or: aws configure / aws sso login
cdp configure
----

Pull the published image (or link:#_developer_guide_build_tag_and_push[build locally]):

[source,bash]
----
docker pull clouderapartners/cdp-public-cloud-hol-provisioner:latest
----

=== 2. Prepare userconfig

[source,bash]
----
mkdir -p ~/hol-userconfig
cp configuration/configfile.example ~/hol-userconfig/configfile
# Edit required keys: AWS_REGION, WORKSHOP_NAME, DOMAIN, HOSTEDZONEID, etc.
# Optional: place <AWS_KEY_PAIR>.pem in the same directory
----

=== 3. Provision

[source,bash]
----
docker run --rm \
  -v ~/hol-userconfig:/userconfig \
  -v $HOME/.cdp:/root/.cdp \
  -v $HOME/.aws:/root/.aws \
  clouderapartners/cdp-public-cloud-hol-provisioner:latest provision
----

Workshop access details are written to `~/hol-userconfig/{WORKSHOP_NAME}.txt`.

==== Optional: run in background (`-d`)

Provision and destroy can take 1–3+ hours. The commands above use `docker run --rm` and stream output to your terminal.

To run detached instead, omit `--rm`, add `-d`, and set a container name:

[source,bash]
----
WORKSHOP=myworkshop   # same as WORKSHOP_NAME in configfile

docker run -d --name hol-${WORKSHOP}-provision \
  -v ~/hol-userconfig:/userconfig \
  -v $HOME/.cdp:/root/.cdp \
  -v $HOME/.aws:/root/.aws \
  clouderapartners/cdp-public-cloud-hol-provisioner:latest provision
----

Follow the container log:

[source,bash]
----
docker logs -f hol-${WORKSHOP}-provision
----

When the run finishes, remove the container:

[source,bash]
----
docker rm hol-${WORKSHOP}-provision
----

During data service deploys, per-service Ansible logs are also written to `~/hol-userconfig/.{WORKSHOP_NAME}/logs/` (`CDW.log`, `CDE.log`, `CAI.log`, `CDF.log`):

[source,bash]
----
tail -f ~/hol-userconfig/.myworkshop/logs/CDW.log
----

NOTE: Do not combine `--rm` with `-d` if you need `docker logs -f` after the container exits.

To keep foreground mode and save output to a file:

[source,bash]
----
docker run --rm \
  -v ~/hol-userconfig:/userconfig \
  -v $HOME/.cdp:/root/.cdp \
  -v $HOME/.aws:/root/.aws \
  clouderapartners/cdp-public-cloud-hol-provisioner:latest provision \
  2>&1 | tee ~/hol-userconfig/provision.log
----

=== 4. Destroy

Use the same `userconfig` directory (state is stored under `~/hol-userconfig/.{WORKSHOP_NAME}/`):

[source,bash]
----
docker run --rm \
  -v ~/hol-userconfig:/userconfig \
  -v $HOME/.cdp:/root/.cdp \
  -v $HOME/.aws:/root/.aws \
  clouderapartners/cdp-public-cloud-hol-provisioner:latest destroy
----

Use the same optional `-d` / `docker logs -f` pattern as provision (replace the container name, e.g. `hol-${WORKSHOP}-destroy`).

== Key constraints

|===
| Setting | Rule

| `PROVISION_CAII:yes`
| `LOCAL_MACHINE_IP` **must not** be `0.0.0.0/0` — use Jenkins agent IP or Cloudera VPN

| `OWNER` / `pse-owner` tag
| Default `pse-apac@cloudera.com`; cannot use `owner` (CDP reserved tag)

| Credentials
| Mount `~/.cdp` and `~/.aws`, or pass keys via configfile (see link:../../../docs/oncloud/configfile-reference.adoc[configfile reference])
|===

== Developer guide — build, tag, and push

This directory is the working tree for image development. Use these steps when you change provisioner code, entrypoint scripts, or Ansible playbooks.

=== Install Docker

Follow the link:https://docs.docker.com/engine/install/[official Docker installation guide] for your platform.

=== Build

From the repository root (or `cd` into this directory):

[source,bash]
----
cd OnCloud/AWS/build/
docker build --platform linux/amd64 \
  --build-arg TF_QUICKSTART_VERSION=v0.15.0 \
  -t hol-aws:latest .
docker images | grep hol-aws
----

`TF_QUICKSTART_VERSION` pins the `cdp-tf-quickstarts` tag baked into the image (see `Dockerfile`). Override it when testing a newer quickstart release.

=== Log in to Docker Hub

[source,bash]
----
docker login
----

Use a Docker Hub account with push access to `clouderapartners/cdp-public-cloud-hol-provisioner`.

=== Tag and push

[source,bash]
----
docker tag hol-aws:latest clouderapartners/cdp-public-cloud-hol-provisioner:latest
docker push clouderapartners/cdp-public-cloud-hol-provisioner:latest
----

To publish an additional version tag:

[source,bash]
----
docker tag hol-aws:latest clouderapartners/cdp-public-cloud-hol-provisioner:<version>
docker push clouderapartners/cdp-public-cloud-hol-provisioner:<version>
----

NOTE: Images built on one platform may not run on another. For multi-arch publish (as in `Jenkinsfile.Build`), use link:https://docs.docker.com/build/building/multi-platform/[Docker multi-platform builds] (`docker buildx`).

=== Run your local image

[source,bash]
----
docker run --rm \
  -v ~/hol-userconfig:/userconfig \
  -v $HOME/.cdp:/root/.cdp \
  -v $HOME/.aws:/root/.aws \
  hol-aws:latest provision
----
