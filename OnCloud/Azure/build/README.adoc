= AutoClouderaDeploy — Azure HoL Provisioner
:toc: preamble
:icons: font

Container-based automation that provisions a **disposable** Cloudera Data Platform Public Cloud Hands-on Lab stack on Azure — environment, datalake, data services (CAI, CDW, CDE, CDF), optional Keycloak SSO, and workshop users.

Detailed reference: link:../../../docs/oncloud/azure-provisioner.adoc[Azure provisioner guide] · link:../../../docs/oncloud/configfile-reference.adoc[configfile reference]

== Quick start

=== 1. Prerequisites

[source,bash]
----
az login
cdp configure
aws configure    # Route53 DNS for Keycloak when using DOMAIN/HOSTEDZONEID
----

Pull the published image (or link:#_developer_guide_build_tag_and_push[build locally]):

[source,bash]
----
docker pull clouderapartners/cdp-public-cloud-hol-provisioner-azure:latest
----

=== 2. Prepare userconfig

[source,bash]
----
mkdir -p ~/hol-userconfig
cp configuration/configfile.example ~/hol-userconfig/configfile
# Edit required keys: AZURE_REGION, WORKSHOP_NAME, DOMAIN, HOSTEDZONEID, etc.
# Optional: place <SSH_KEY_NAME>.pem in the same directory
----

=== 3. Provision

[source,bash]
----
docker run --rm --platform linux/amd64 \
  -v ~/hol-userconfig:/userconfig \
  -v $HOME/.cdp:/root/.cdp \
  -v $HOME/.azure:/root/.azure \
  -v $HOME/.aws:/root/.aws \
  clouderapartners/cdp-public-cloud-hol-provisioner-azure:latest provision
----

Workshop access details are written to `~/hol-userconfig/{WORKSHOP_NAME}.txt`.

==== Optional: run in background (`-d`)

Provision and destroy can take 1–3+ hours. The commands above use `docker run --rm` and stream output to your terminal.

To run detached instead, omit `--rm`, add `-d`, and set a container name:

[source,bash]
----
WORKSHOP=myworkshop   # same as WORKSHOP_NAME in configfile

docker run -d --name hol-${WORKSHOP}-provision \
  --platform linux/amd64 \
  -v ~/hol-userconfig:/userconfig \
  -v $HOME/.cdp:/root/.cdp \
  -v $HOME/.azure:/root/.azure \
  -v $HOME/.aws:/root/.aws \
  clouderapartners/cdp-public-cloud-hol-provisioner-azure:latest provision
----

Follow the container log:

[source,bash]
----
docker logs -f hol-${WORKSHOP}-provision
----

When the run finishes, remove the container:

[source,bash]
----
docker rm hol-${WORKSHOP}-provision
----

During data service deploys, per-service Ansible logs are also written to `~/hol-userconfig/.{WORKSHOP_NAME}/logs/` (`CDW.log`, `CDE.log`, `CAI.log`, `CDF.log`):

[source,bash]
----
tail -f ~/hol-userconfig/.myworkshop/logs/CDW.log
----

NOTE: Do not combine `--rm` with `-d` if you need `docker logs -f` after the container exits.

To keep foreground mode and save output to a file:

[source,bash]
----
docker run --rm --platform linux/amd64 \
  -v ~/hol-userconfig:/userconfig \
  -v $HOME/.cdp:/root/.cdp \
  -v $HOME/.azure:/root/.azure \
  -v $HOME/.aws:/root/.aws \
  clouderapartners/cdp-public-cloud-hol-provisioner-azure:latest provision \
  2>&1 | tee ~/hol-userconfig/provision.log
----

=== 4. Destroy

Use the same `userconfig` directory (state is stored under `~/hol-userconfig/.{WORKSHOP_NAME}/`):

[source,bash]
----
docker run --rm \
  -v ~/hol-userconfig:/userconfig \
  -v $HOME/.cdp:/root/.cdp \
  -v $HOME/.azure:/root/.azure \
  -v $HOME/.aws:/root/.aws \
  clouderapartners/cdp-public-cloud-hol-provisioner-azure:latest destroy
----

Use the same optional `-d` / `docker logs -f` pattern as provision (replace the container name, e.g. `hol-${WORKSHOP}-destroy`).

NOTE: Image is `linux/amd64`. On Apple Silicon, always include `--platform linux/amd64`.

== Key constraints

|===
| Setting | Rule

| `PROVISION_CAII:yes`
| `LOCAL_MACHINE_IP` **must not** be `0.0.0.0/0`

| `pse-owner` tag
| Required for cost tracking via `ENV_TAGS` (default Jenkins OWNER: `pse-apac@cloudera.com`)

| AWS credentials
| Required for Keycloak Route53 DNS even on Azure deployments

| Credentials
| Mount `~/.cdp`, `~/.azure`, and `~/.aws`, or pass via configfile (see link:../../../docs/oncloud/configfile-reference.adoc[configfile reference])
|===

== Developer guide — build, tag, and push

This directory is the working tree for image development. Use these steps when you change provisioner code, entrypoint scripts, or Ansible playbooks.

=== Install Docker

Follow the link:https://docs.docker.com/engine/install/[official Docker installation guide] for your platform.

=== Build

From the repository root (or `cd` into this directory):

[source,bash]
----
cd OnCloud/Azure/build/
docker build --platform linux/amd64 \
  --build-arg TF_QUICKSTART_VERSION=v0.15.0 \
  -t hol-azure:latest .
docker images | grep hol-azure
----

`TF_QUICKSTART_VERSION` pins the `cdp-tf-quickstarts` tag baked into the image (see `Dockerfile`). Override it when testing a newer quickstart release.

=== Log in to Docker Hub

[source,bash]
----
docker login
----

Use a Docker Hub account with push access to `clouderapartners/cdp-public-cloud-hol-provisioner-azure`.

=== Tag and push

[source,bash]
----
docker tag hol-azure:latest clouderapartners/cdp-public-cloud-hol-provisioner-azure:latest
docker push clouderapartners/cdp-public-cloud-hol-provisioner-azure:latest
----

To publish an additional version tag:

[source,bash]
----
docker tag hol-azure:latest clouderapartners/cdp-public-cloud-hol-provisioner-azure:<version>
docker push clouderapartners/cdp-public-cloud-hol-provisioner-azure:<version>
----

NOTE: The runtime image is `linux/amd64`. On Apple Silicon, always pass `--platform linux/amd64` for build and run. For multi-arch publish (as in `Jenkinsfile.Build`), use link:https://docs.docker.com/build/building/multi-platform/[Docker multi-platform builds] (`docker buildx`).

=== Run your local image

[source,bash]
----
docker run --rm --platform linux/amd64 \
  -v ~/hol-userconfig:/userconfig \
  -v $HOME/.cdp:/root/.cdp \
  -v $HOME/.azure:/root/.azure \
  -v $HOME/.aws:/root/.aws \
  hol-azure:latest provision
----
